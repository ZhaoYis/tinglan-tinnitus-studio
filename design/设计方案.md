## 1. 设计依据：先量现状，再动手

设计之前对现有界面做了一次自动化审计（390×844 移动端 + 1280 桌面端，无头浏览器实测）：

| 指标 | 现状实测 | 判断 |
|---|---|---|
| 首页内容高度 | **2101px**（约 2.5 屏） | 睡前单手操作，主任务被 5 个面板稀释 |
| 主播放按钮 | 57×57，混在面板里，与 40×40 停止按钮并列 | 唯一的核心动作没有视觉主导权 |
| 触控目标 < 44×44 | **40 个**，最小 29×29；滑杆命中区仅 16px 高 | 睡前、半躺着操作，失误率会很高 |
| 文本对比度 < 4.5:1 | **46 处** | 不满足 WCAG AA |
| 字号分布 | 12px × 86、11px × 54、10px × 27、9px × 17 | 昏暗环境下小字几乎不可读 |
| 图标 | **27 种** Unicode 符号（♧ ☾ ▥ ≋ ✿ ⌕ ◷ ♙ …） | 跨平台字形不一致，语义依赖猜 |
| 桌面端 | 700px 单列居中 + 移动端底部 tab | 1280 宽屏浪费近一半，导航习惯错位 |
| 主题 | 仅浅色（大面积 `#f7f4ec`） | 与「睡前使用」这一核心场景直接冲突 |

最后一条是这次重做的主因：**这是个睡前用的工具，界面却比手机里其他任何页面都亮。**

---

## 2. 四条设计原则

| 原则 | 含义 | 落地方式 |
|---|---|---|
| **一屏一件事** | 首页只回答「现在要不要开始」 | 首页 = 大主控 + 当前方案 + 音量；其余全部降级 |
| **夜间优先** | 默认深色低亮度，暖色作主色（低蓝光），浅色作为可选项 | 双主题令牌，默认 `data-theme="night"` |
| **触控优先于密度** | 44px 是底线，不是建议 | 滑杆命中区从 16px 提到 44px；最小按钮 44×44 |
| **安全信息不靠小字** | 音量与不适提示是产品红线，不能被灰色小字淹没 | 独立的琥珀色提示条，13px 起 |

## 3. 设计令牌

### 3.1 颜色（含实测对比度）

夜间主题（默认）：

| 用途 | 值 | 与背景对比度 |
|---|---|---|
| 页面背景 | `#0a100f` | — |
| 卡片 | `#111a19` / `#16211f` | — |
| 正文 | `#e9f0ed` | **16.59:1** |
| 次要文字 | `#a3b6b1` | **9.03:1** |
| 三级文字 | `#7d918c` | **5.31:1**（卡片上） |
| 主操作（暖琥珀） | `#f2b880` | **10.07:1**（卡片上） |
| 主按钮文字 | `#241708` | **9.94:1**（琥珀底上） |

日间主题：

| 用途 | 值 | 与背景对比度 |
|---|---|---|
| 页面背景 | `#f5f1e8` | — |
| 卡片 | `#fffdf9` | — |
| 正文 | `#1e2b28` | **13.02:1** |
| 次要文字 | `#51625e` | **6.34:1** |
| 三级文字 | `#5b6d68` | **5.39:1** |
| 主操作（深棕） | `#8a5a20` | **5.80:1** |
| 主按钮文字 | `#fffdf9` | **5.80:1** |

语义辅助色：`--teal #5cc9bd`（夜间）/ `#16746c`（日间）用于焦点环与链接；`--danger #e79084` / `#a8412f` 仅用于破坏性操作。

> 半透明叠加一律用 `--accent-rgb: 242 184 128` 这类可复用的 RGB 分量令牌，**不硬编码颜色**。日间主题曾因两处硬编码的夜间暖色导致光晕与波形失真，已修为令牌。

### 3.2 字号

`13 / 15 / 17 / 20 / 26 / 34`，正文与说明文字下限 13px。
仅品牌署名（11px）与角标（11px）例外，二者都不是可读内容。

行高 1.6；标题 `letter-spacing: -.02em`（中文大字号收紧更精神）。

### 3.3 间距 / 圆角 / 阴影

- 间距 4px 基准：`4 / 8 / 12 / 16 / 24 / 32 / 48`
- 圆角：卡片 22px、大卡 28px、控件 16px、药丸 999px
- 阴影两级：`--shadow-1`（静态卡片）、`--shadow-2`（浮层 / 底栏）

### 3.4 动效

- `--ease: cubic-bezier(.22,.61,.36,1)`，`140 / 240 / 420ms` 三档
- 播放态用 4.2s 呼吸环 + 波形错峰摆动（每根延迟 −37ms），暗示"声音在流动"
- **`prefers-reduced-motion: reduce` 时全部降为 0.001ms**，不只关动画时长，也关循环

## 4. 信息架构

### 4.1 从「仪表盘」到「单任务」

旧首页把 5 个面板平铺：频谱 / 预设 / 音轨 / 全局设置 / 观察记录。用户每次都要在 2101px 里找播放按钮。

新结构：

```text
今晚（首页）
├── 当前方案名 + 三轨摘要        ← 一眼知道"现在是什么声音"
├── 128px 主控球                 ← 唯一焦点，开始/暂停
├── 时长 · 渐入 · 数字增益        ← 一行次要信息
├── 波形（播放时流动）
├── 音量卡                      ← 数字增益 + 听感词（轻/适中/较响）
├── 换个声音（横向 chips）        ← 替代原来的 4 张预设大卡
├── 更多设置（折叠）             ← 时长、渐入渐出、自动停止、进调音台
└── 安全提示条
```

结果：**2101px → 1074px**，主控球落在距顶 217px 处，单手拇指可达。

### 4.2 导航

| 断点 | 导航 | 理由 |
|---|---|---|
| < 1024px | 底部浮动胶囊，4 项 | 移动端既有习惯，不重新发明 |
| ≥ 1024px | 左侧 264px 竖栏 | 底部 tab 是移动端范式，照搬到宽屏会别扭；侧栏同时给出「本地运行 / 数据不出设备」的常驻声明 |

桌面主列 820px 居中，不再让 1280 屏幕浪费一半。

### 4.3 页面职责

| 视图 | 唯一职责 | 明确不做 |
|---|---|---|
| 今晚 | 开始 / 暂停，微调音量 | 不放音轨细节、不放记录统计 |
| 声音库 | 找到并加载一个方案 | 不做音轨级编辑（进调音台） |
| 记录 | 看趋势、看日志、导出 | 不做数据录入（弹窗完成） |
| 我的 | 身份、统计、设置、隐私 | 不重复首页功能 |

## 5. 关键界面说明

### 5.1 今晚
- 主控球 128px，琥珀径向渐变 + 外发光 + 呼吸环；按下 `scale(.97)` 给物理反馈
- 文案随状态切换：「开始播放」→「正在播放 · 轻触暂停」，`aria-pressed` 同步
- 音量滑杆把百分比翻译成**听感词**（<20 轻 / <45 适中 / <70 较响 / 其余很响），因为「18%」对用户没有意义
- 高级设置折叠在 `details` 里：默认只露出折叠条，需要时再展开

### 5.2 声音库
- 搜索框在宽屏下限制 460px，避免拉满整列
- 场景 chip 单选互斥（`aria-pressed`）
- 推荐横幅只留一个 CTA，文案给"今晚"而不是"立即购买"式的推销感
- 预设卡片 2 列（移动）/ 3 列（≥720px），每卡仅名称 + 声音构成 + 场景角标

### 5.3 记录
- 概览 / 趋势 / 日志用分段控件切换，**替代原来的 5 个面板纵向堆叠**
- 图表极简：一条平滑曲线 + 淡出填充 + 末点高亮，无坐标轴、无网格
- 固定一句话解释「0–10 是自评，不是听力检测」——避免用户误读为医学指标

### 5.4 我的
- 统计三宫格、菜单列表（52px 行高，`chev` 指示可进入）
- 破坏性操作「清除本地记录」用 `--danger` 单独着色
- 底部再次声明"不是临床验证的治疗设备"

## 7. 可访问性（实测，非声明）

| 项目 | 标准 | 本期结果 |
|---|---|---|
| 文本对比度 | WCAG AA 4.5:1（大字 3:1） | 夜间 **0** 处不达标，日间 **0** 处 |
| 触控目标 | ≥44×44 | 移动端 **0** 处不达标，桌面端 **0** 处 |
| 键盘可达 | 全部交互可 Tab 到达 | 按钮/输入/折叠/分段均为原生元素 |
| 焦点可见 | 2px `--teal` 环，offset 3px | `:focus-visible` 全局定义 |
| 对话框 | 打开时焦点进入，Esc 关闭 | 打开聚焦「开始今晚」，关闭后焦点回到触发按钮 |
| 动效偏好 | 尊重 `prefers-reduced-motion` | 动画与过渡统一降级 |
| 图标语义 | 不依赖字形 | 19 个内联 SVG symbol；纯装饰图标 `aria-hidden` |
| 状态播报 | 动态变化可播报 | 播放状态用 `aria-pressed`，提示用 `aria-live` |

> 审计脚本对渐变背景做了跳过处理：单一色值无法判定渐变上的对比度，强行计算会产生假阳性（旧界面把播放箭头误判为 1.10:1 就是这个原因）。

## 8. 开发交接

### 8.1 令牌落地

`prototype.html` 的 `:root` / `[data-theme]` 段可**整段复制**进 `styles.css` 顶部，文件名与变量名无需改动。原 `styles.css` 已有 `--bg/--ink/--muted/--teal` 等变量，建议一次性改名对齐，避免两套令牌并存。

### 8.2 元素映射

| 原型 | 现有实现 | 说明 |
|---|---|---|
| `#orb` + `#orbLabel` | `#playBtn` / `.play-primary` | 播放/暂停合并为一个切换按钮 |
| `#vol` + `#volLevel` | `#masterVolume` + `#masterVal` | 保留数字百分比，新增听感词 |
| `#metaGain` | `#heroStatus` 附近 | 显示 `数字增益 N%` |
| `.wave` | `#spectrum`（canvas） | 原型用 CSS 条；接入实时频谱时替换为 canvas，尺寸逻辑不变 |
| `#q` / `.chips` | `#presetSearch` / `#categoryChips` | 结构一致 |
| `.grid` / `.preset` | `#presetGrid` | 卡片更简，去掉进度条式装饰 |
| `.segmented` | `#trendSegments` | 语义从「7/30/90 天」变为「概览/趋势/日志」，需同步调整渲染逻辑 |
| `#chart` | `#trendCanvas` | 绘图函数可直接复用，仅换配色与内边距 |
| `.log li` | `#sleepRows` / `#sessionRows` / `#journalRows` | 三处共用同一行组件 |
| `#overlay` / `.dialog` | `#overlay` / `.dialog` | 结构不变，补焦点管理 |
| `.tabbar` / `.sidenav` | `.tabbar` | 新增侧栏，同一份 `data-nav` 驱动 |

### 8.3 分阶段建议

不要一次替换整站，按风险从低到高：

1. **令牌层**（1 天，零逻辑风险）：替换 CSS 变量、字号、间距、圆角，先让旧布局吃到新配色
2. **图标层**：把 27 种 Unicode 符号换成内联 SVG symbol，逐个替换并肉眼核对
3. **首页重排**：`#page-home` 改为「今晚」结构，先接 `playBtn` / `masterVolume` 两个真实控件
4. **导航双形态**：≥1024px 启用侧栏，移动端保留底栏
5. **记录页分段**：`trendSegments` 语义调整，需同步改 `renderRecords`
6. **声音库卡片简化**：最后做，纯装饰改动

每一步都可用现有 `node --test tests/core.test.mjs` + 浏览器冒烟做回归，不涉及音频链路，风险可控。

## 9. 验证记录

原型在无头 Chrome 中实跑，不是静态稿：

```
交互      四视图切换、播放/暂停、主题切换、分段切换、对话框开合    全部通过
运行时    控制台异常 / 资源错误                                 0
对比度    夜间 0 处、日间 0 处 低于 4.5:1
触控      移动 0 / 日间 0 / 桌面 0 处 小于 44×44
布局      移动端 390×844 内容高度 1074px；桌面 1440 主列 820px，侧栏生效、底栏隐藏
文件直开  file:// 协议打开，波形 47 根、图表已绘制、播放态可切换、无报错
遮挡      预设/记录/我的 三视图滚到底部，最后元素与底栏间距 20 / 144 / 95px，无遮挡
```

过程中修掉的真实问题：

1. **桌面品牌 logo 掉到导航下方** —— `.topbar` 与 `.sidenav` 共用同一网格单元格，`align-items:center` 把它垂直居中了。改为品牌独占第一行、导航第二行。
2. **日间主题光晕与波形失真** —— 两处硬编码 `rgba(242,184,128,…)`。改为 `--accent-rgb` 令牌。
3. **分段控件 38px、搜索框 40px** —— 低于 44px 基线。已提到 44px。
4. **分隔圆点不显示** —— `<i>` 默认 inline，宽高不生效。补 `display:inline-block`。
5. **一处"看起来压住内容"** —— 全页截图里底栏盖住了预设卡片，实测三视图 `clear: true`，是固定元素在全页截图中的伪影，未做无谓修改。

## 10. 未覆盖与取舍

原型是**视觉与交互方案**，以下状态没有画，实施时需补齐：

- 播放中的「结束并记录」次级入口（现有 `#stopBtn` 的语义不能直接并进主控球）
- 首次使用空状态、IDB 不可用降级提示、播放失败错误态
- 本地音频上传、导出 WAV 的时长选择弹窗、备份导入确认
- 自定义预设的编辑与删除流程
- 调音台（原「声音轨道」面板）的完整形态——本期只留入口

刻意没做的：

- **不加二级 Tab、不加侧边抽屉**：四个视图已经够用，再加一层会让睡前操作路径变长
- **不做纯图形化主控**（如环形进度拖拽调音量）：睡前视野与精细动作都差，大按钮更稳
- **不引入设计系统的运行时依赖**：令牌就是 CSS 变量，零构建、零体积
